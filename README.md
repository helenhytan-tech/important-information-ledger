# 重要信息记录系统

双击 **启动信息记录系统.command**，浏览器会打开系统。使用期间保留启动窗口。

如果希望以后不再手动启动：双击 **安装后台运行.command** 一次。脚本会把运行代码复制到用户 Library 的后台目录，并把本机数据安全复制到同一目录，绕开 macOS 对“文稿”目录的后台访问限制；原 `data` 文件夹不会删除。macOS 会在登录后自动启动服务，并在服务异常退出时自动重启。安装完成后，在浏览器地址栏按 `⌘D` 把 `http://127.0.0.1:8766/` 添加到收藏夹。浏览器收藏保存的是地址；后台运行脚本负责保证地址背后的服务一直可用。需要停止时双击 **卸载后台运行.command**，不会删除数据。

- **录入**：直接在表格中填写，编辑后自动保存；新增记录可点击右上角按钮。
- **粘贴**：从 Excel 复制数据区域，点击起始单元格按 ⌘V。也可点击“粘贴内容”打开粘贴框。支持含换行的 Excel 单元格，自动跳过完整表头。
- **筛选**：全局搜索覆盖 9 个字段；“条件筛选”中输入为模糊匹配，点选为精确匹配，不同字段组合使用。筛选中粘贴只写入可见行，行数不足时提示先重置筛选。
- **导出**：可导出全部记录或当前筛选结果，格式为 `.xlsx`，字段全部按文本保存。
- **撤销**：可撤销本次打开期间最近 30 次编辑操作，删除行后也可撤销。
- **本机数据**：记录保存在 `data/records.json`，不会上传。备份或迁移时复制整个项目文件夹。关闭浏览器前确认右上角显示“已保存到本机”。

系统仅监听本机地址 http://127.0.0.1:8766 ，使用 Python 3 标准库，无需安装第三方包。记录是本机明文文件，“密码提示”用于填写提示信息。

## 备份与恢复

- 每次成功保存都生成完整快照；覆盖前也保留旧记录。备份写入失败时不覆盖正式记录。
- 备份保存在 `data/backups/`。成功保存后清理超过 30 天的版本，至少保留最新一份；恢复时不会清理旧版本。
- 点击 **备份与恢复 → 预览 → 确认恢复此版本**。恢复前会先备份当前内容。正式文件损坏或缺失时也能打开恢复入口，损坏原文会另存为 `.damaged` 文件。
- **下载当前内容备份** 生成包含全部字段的 JSON 文件，也包含页面中尚未保存的内容。请定期把它另存到云盘或其他硬盘。通过 **从备份文件恢复** 导入、预览后恢复。
- 自动备份在同一台电脑，不能防止硬盘损坏；下载文件不会自动上传或同步到云盘。
- 自动历史仅从此功能启用后开始，无法找回此前未保留的版本。浏览器崩溃前尚未成功保存的修改仍可能丢失。

## 导出格式

在表格工具栏选择 Excel、PDF、HTML 或 PNG，再点击“导出全部”或“导出筛选结果”。各表的导出与筛选只包含当前表。PDF 自动分页，PNG 单页直接下载、多页打包 ZIP；HTML 是可独立打开的文件。

PDF/PNG 使用本机 Codex 附带的 Python、ReportLab、Pillow 和系统 Arial Unicode 字体。迁移到其他电脑时需要对应运行环境；Excel/HTML 仍仅使用 Python 标准库。


## 独立表格

“工作、重要、个人、其他”各自是一张独立表，表内“分类”可以自由填写，不决定记录属于哪张表。“信息记录”是保留原有未分组内容的独立表。“搜索与筛选”作用于当前表。

每张表的数据保存在 `data/tables/<表名>/records.json`，备份在该目录下的 `backups/`。表名为 `work`、`important`、`personal`、`other`、`general`。下载备份和恢复也只作用于当前表。切换前会先保存，保存失败时保留当前表，避免丢失修改。

首次升级先备份旧数据，再把原有分类恰为工作、重要、个人、其他的记录迁入对应表，其余保留在信息记录表。分类单元格原文不变。原 `data/records.json` 和旧备份继续保留，升级后不再用于新表编辑。

## 电脑操作表

新增独立“电脑操作”页面，字段为产品、名称、操作方式、快捷键、备注、其他。支持六列粘贴、筛选、四种格式导出和备份恢复；数据在 `data/tables/computer/records.json`，备份在同目录的 `backups/`。

## 在另一台 Mac 使用和共用云端数据

运行 `打包到另一台Mac.command` 会在项目上一级生成一个 Mac 压缩包。压缩包不包含本机的 `data` 和 `.git`，不会把已有记录复制出一份。

1. 在两台 Mac 上登录同一个云盘账号，并在云盘中建立一个专用文件夹，例如“重要信息记录系统数据”。
2. 双击 `设置云端数据位置.command`，输入这个云盘文件夹的本机路径。它会生成 `data-location.txt`；两台 Mac 的路径写法可以不同，只要指向同一个云盘文件夹。也可以手动参考 `data-location.txt.example`。
3. 双击 `启动信息记录系统.command`。系统会在该云盘文件夹中创建 `records.json`、`tables/` 和各表的 `backups/`。

iCloud Drive 的路径通常是 `/Users/你的用户名/Library/Mobile Documents/com~apple~CloudDocs/重要信息记录系统数据`；OneDrive 的路径通常在 `/Users/你的用户名/Library/CloudStorage/` 下。路径仅保存在本机的 `data-location.txt`，不会进入压缩包或 Git。

云盘同步适合两台电脑轮流编辑。不要在两台电脑同时打开同一张表并保存：云盘同步延迟可能让两个版本都先后写入。系统仍会检查 revision 并拒绝已过期页面的覆盖；发生冲突时，先下载当前 JSON 备份，再刷新页面。首次使用或迁移前，建议先用“下载当前内容备份”留一份独立副本。

如果使用云盘数据，先完成云盘登录和 `设置云端数据位置.command`，再安装后台运行；这样后台服务会直接使用云盘中的 JSON 数据目录。

## 导入 JSON

表格工具栏有 **导入 JSON** 按钮。它接受系统下载的 JSON 备份，也接受包含 `rows` 二维数组的 JSON 文件；导入前会预览前 20 行，确认后替换当前表，并自动备份原内容。导入的列数和列名必须与当前表一致。

## 全部表格合并导出

工具栏的“导出全部表格”会把所有独立表合成一个文件：Excel 为多个工作表，PDF 为连续分页，HTML 为按表分开的区块，PNG 为包含全部页面的 ZIP。
# 云端静态部署与 JSON 同步

项目也可以作为纯静态网页部署到 GitHub Pages 或 Cloudflare Pages。静态版不会上传记录：每张表保存在当前浏览器的 `localStorage`，跨电脑使用时，在“备份与恢复”中下载 JSON，到另一台电脑导入即可。仓库和部署目录不包含 `data/`、备份文件或任何记录内容。

生成部署目录：

```bash
python3 build_static.py
```

`dist/` 只包含 `index.html`、`app.js`、`core.js` 和 `styles.css`。Cloudflare Pages 部署时将 `dist` 作为上传目录；如果使用 GitHub Pages，可在工作流中运行上面的构建命令后发布 `dist`。本机继续使用 `启动信息记录系统.command` 时，仍会通过 Python 服务保存本地 `data/`，不会影响静态版。
